# 📸 Фотокамера — PWA с автозагрузкой в Supabase

Веб-приложение, которое устанавливается на экран «Домой» iPhone и работает как обычная камера:
открыл — сразу видишь кадр, нажал кнопку (на экране или Bluetooth-кнопку) — снимок **автоматически**
уходит в ваш Supabase. Без диалогов, без «куда сохранить», без подтверждений.

## Что умеет

- **Камера открывается сразу** при запуске — живой предпросмотр во весь экран.
- **Съёмка двумя способами:**
  - круглая кнопка внизу экрана (как в штатной камере);
  - **любая клавиша** Bluetooth-клавиатуры/кнопки (Enter, пробел, стрелка, буква).
    Одно нажатие = одно фото; удержание клавиши и модификаторы (Shift, Ctrl…) не срабатывают.
- **Автозагрузка** в Supabase Storage — сразу после снимка, без вопросов.
- **Счётчик** «Фото: N» за текущую сессию.
- **Очередь отправки** в IndexedDB: если пропала сеть — снимок не теряется, отправится позже
  (очередь переживает перезагрузку страницы).
- **Лента** — открывается только по тапу на иконку 🖼, показывает ваши снимки по подписанным ссылкам.
- **Вход по email/паролю** (Supabase Auth); сессия запоминается на устройстве.
- **Экран не гаснет** — Screen Wake Lock + автопродление каждые 5 минут.
- **Самодиагностика** — статусная строка показывает причину, если что-то не так
  («bucket не найден», «нет прав (политики)», «нет сети»).
- **Без звука и вибрации** — по задумке, чтобы не мешать долгой съёмке.

## На каких устройствах работает

| Устройство | Браузер | Что работает |
|---|---|---|
| iPhone / iPad, iOS 16.4+ | Safari | камера, съёмка, вход, «На экран Домой», Wake Lock, Bluetooth-клавиатура |
| Android | Chrome | камера, съёмка, вход, установка PWA, Bluetooth-клавиатура |
| Компьютер | Chrome / Edge / Safari | камера и съёмка (можно установить как приложение в Chrome/Edge) |

**Обязательные условия:**

- **HTTPS** — без него браузер не даст доступ к камере (localhost — исключение).
- **Разрешение на камеру** — спрашивается один раз при первом запуске.
- **Bluetooth-кнопка должна быть HID-клавиатурой** и отправлять клавишу (Enter, пробел, стрелку).
  Кнопки, которые шлют «громкость +/−», веб-страница на iPhone **не увидит** — это ограничение iOS.
- Для iPhone: «Поделиться → На экран „Домой"» — приложение откроется полноэкранно, без адресной строки.

## Как устроена программа

```
index.html               интерфейс: камера, кнопка, счётчик, лента, экран входа
app.js                   вся логика (ES-модуль)
config.js                настройки проекта Supabase
manifest.webmanifest     описание PWA (имя, иконки, цвет)
sw.js                    service worker: сеть → кэш (работает при сбое сети)
icon-180.png, icon-512.png   иконки приложения
```

### Поток данных

1. **Загрузка** → регистрируется service worker → проверяется сессия Supabase Auth.
2. **Сессии нет** → показывается экран входа (email + пароль, или регистрация).
3. **Сессия есть** → `getUserMedia` (задняя камера, предпочтительно 1920×1440) → `<video>`.
4. **Снимок** (кнопка или клавиша) → кадр рисуется в `<canvas>` → `toBlob('image/jpeg', 0.82)`,
   ширина ограничена 1600 px (~200–400 КБ на файл).
5. **Blob попадает в очередь** IndexedDB → фоновый `drain()` загружает его в Storage:
   `photos/<uid>/shot-ГГГГММДД-ЧЧММСС-ммм-рандом.jpg`.
6. **Ошибка сети** → элемент остаётся в очереди, повтор каждые 8 секунд.
7. **Лента** → `list()` своей папки → `createSignedUrl(..., 600)` (ссылка живёт 10 минут) → миниатюры.
8. **Wake Lock** запрашивается при старте и продлевается каждые 5 минут; при возврате
   на страницу камера переподключается сама.

### Ключевые места в коде

| Что | Где |
|---|---|
| Включение камеры | `startCamera()` |
| Снимок и качество JPEG | `capture()` (`1600` px и `0.82`) |
| Имя файла | `makeName()` |
| Загрузка/очередь | `drain()`, `queueAdd()` |
| Триггер с клавиатуры | обработчик `keydown` (любая клавиша, кроме модификаторов) |
| Лента | `openGallery()` |
| Вход | `signInWithPassword` / `signUp` |
| Экран не гаснет | `requestWake()` |

## Куда отправляются файлы

- В **Supabase Storage**, bucket с именем из `SUPABASE_BUCKET` (по умолчанию `photos`).
- Путь: **`<uid-пользователя>/shot-<дата>-<время>-<мс>-<рандом>.jpg`**.
- Bucket **приватный**: прямой публичной ссылки на файл нет.
- Доступ — только **вошедшему пользователю** и только **в его папку** (правила RLS).
- Просмотр — по **подписанным ссылкам**, которые живут 10 минут.
- Политик на **удаление и перезапись нет** — файлы нельзя удалить или заменить через API.

Можно направить всё в **любой свой проект Supabase** (или self-hosted), поменяв `config.js`.
В один bucket можно писать из нескольких приложений — главное, чтобы совпадали имена bucket и политики.

## Своя копия за 10 минут

### 1. Проект Supabase

1. Зарегистрируйтесь на [supabase.com](https://supabase.com) → **New project** (план Free).
2. Запишите **Project URL** и **publishable/anon ключ**: *Settings → API*.

### 2. Bucket

*Storage → New bucket* → имя `photos` → **Public bucket выключен** → Create.

### 3. Пользователь

*Authentication → Users → **Add user*** → email + пароль, галка **Auto Confirm User**.
(Альтернатива: оставить регистрацию включённой и зарегистрироваться прямо в приложении —
но в настройках проекта может требоваться подтверждение почты.)

### 4. Политики

*SQL Editor* → выполнить SQL из раздела [Политики Supabase](#политики-supabase-sql).

### 5. Настройки приложения

Отредактируйте `config.js` (см. ниже).

### 6. Публикация

Нужен любой бесплатный статический хостинг с HTTPS:

- **GitHub Pages** — положить файлы в репозиторий → *Settings → Pages → Deploy from a branch → main / root*;
- **Netlify Drop** — перетащить папку на [app.netlify.com/drop](https://app.netlify.com/drop);
- **Vercel** — импорт папки/репозитория.

### 7. Телефон

Открыть адрес в Safari → «Разрешить» камеру → «Поделиться → На экран „Домой"» → войти → снимать.

## Настройки `config.js`

```js
window.APP_CONFIG = {
  SUPABASE_URL: "https://ВАШ-ПРОЕКТ.supabase.co",
  SUPABASE_KEY: "sb_publishable_...",   // публичный ключ, НЕ service_role!
  SUPABASE_BUCKET: "photos",
  USE_UID_FOLDERS: true
};
```

| Параметр | Что значит |
|---|---|
| `SUPABASE_URL` | адрес проекта Supabase |
| `SUPABASE_KEY` | **публичный** (publishable/anon) ключ. Лежит в коде сайта — это нормально: доступ ограничивают правила RLS |
| `SUPABASE_BUCKET` | имя bucket в Storage (регистр важен) |
| `USE_UID_FOLDERS` | `true` — каждый пользователь пишет в свою папку (рекомендуется). `false` — все файлы в корень bucket (проще, но небезопасно) |

> ⚠️ Никогда не вставляйте в `config.js` ключ **service_role / secret** — он даёт полный доступ
> ко всему проекту и его нельзя держать в публичном коде.

## Политики Supabase (SQL)

Закрытый вариант: чтение и запись — только вошедшему, только в свою папку.

```sql
-- убрать открытые политики, если они были
drop policy if exists "upload photos" on storage.objects;
drop policy if exists "read photos"   on storage.objects;
drop policy if exists "anon upload"   on storage.objects;
drop policy if exists "anon read"     on storage.objects;

create policy "own upload"
on storage.objects for insert
to authenticated
with check (
  bucket_id = 'photos'
  and (storage.foldername(name))[1] = auth.uid()::text
);

create policy "own read"
on storage.objects for select
to authenticated
using (
  bucket_id = 'photos'
  and (storage.foldername(name))[1] = auth.uid()::text
);
```

Проверка:

```sql
select policyname, cmd, roles
from pg_policies
where schemaname = 'storage' and tablename = 'objects';
```

Политик `delete`/`update` нет — это значит, что файлы нельзя удалить или перезаписать через API.

**Вариант «без входа»** (только для экспериментов!) — открыть bucket анонимам:

```sql
create policy "anon upload" on storage.objects for insert
to anon with check (bucket_id = 'photos');

create policy "anon read" on storage.objects for select
to anon using (bucket_id = 'photos');
```

При таком варианте ставьте `USE_UID_FOLDERS: false`, и помните: **любой, кто знает ключ из кода,
сможет заливать и читать файлы**. Для личных фото так делать не стоит.

## Как менять код

- **Качество и размер снимка** — в `capture()`: `1600` (максимальная ширина) и `0.82` (качество JPEG).
- **Имена файлов** — `makeName()`. Формат подобран так, чтобы файлы сортировались по времени.
- **Какие клавиши делают фото** — обработчик `keydown`: сейчас срабатывает любая клавиша,
  кроме перечисленных в `MODIFIERS`. Можно сузить до Enter/Space/стрелок.
- **Частота повтора очереди** — `setInterval(() => drain(), 8000)`.
- **Срок жизни подписанных ссылок** — `createSignedUrl(..., 600)` (секунды).
- **Сколько фото грузится в ленту** — `list(prefix, { limit: 100 })`.
- **Имя, иконки, цвет** — `manifest.webmanifest` и `<meta>` в `index.html`.
- **Звук/вибрация** — можно добавить через WebAudio (`AudioContext`) и `navigator.vibrate`
  (на iOS вибрация из веба недоступна).

Сборка не нужна: это чистые HTML/CSS/JS, библиотека Supabase подключается с CDN
(`@supabase/supabase-js@2`). Достаточно отредактировать файлы и обновить хостинг.

## Ограничения и нюансы

- **iOS не отдаёт веб-странице вибрацию** — `navigator.vibrate` там не работает.
- **В фоне PWA засыпает**: пока приложение открыто на экране — работает; свернул/заблокировал — нет.
- **Камера только по HTTPS** (кроме localhost).
- **Счётчик сессии** сбрасывается при перезагрузке страницы (это счётчик «за сессию»).
- **Очередь привязана к устройству и браузеру** (IndexedDB). Очистили данные сайта — очередь пропала.
- **Бесплатный Supabase**: 1 ГБ хранилища, проект «засыпает» после ~недели неактивности.
- Для долгих съёмок поставьте на iPhone **Настройки → Экран и яркость → Автоблокировка → Никогда**
  (в приложении есть Wake Lock, но это двойная страховка).
- Если сессия истекла — приложение попросит войти снова.
- «Сохранить в Фото» в этой версии нет: снимки живут в Supabase и в ленте приложения.

## Безопасность

- Публичный ключ (`publishable`/`anon`) **не является секретом** — он по задумке лежит в коде.
  Защита строится на правилах RLS, а не на скрытности ключа.
- С закрытыми политиками ключ сам по себе не даёт ничего: список пуст, загрузка/скачивание — отказ.
- **Никогда** не кладите `service_role` в клиентский код.
- Рекомендуется **выключить регистрацию** после создания своего аккаунта:
  *Authentication → Providers → Email → Allow new users to sign up → OFF*.
- Если ключ «утёк» — его можно перевыпустить: *Settings → API → Rotate*. Но помните:
  новый ключ снова окажется в `config.js`.
